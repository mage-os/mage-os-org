We are excited to announce the release of **Mage-OS Distribution 3.0.0**, our first major version. 3.0 rebases the distribution onto **Magento Open Source 2.4.9**, raises the platform baseline to PHP 8.3+, removes Adobe's analytics phone-home stack, brings RMA and Admin Activity Log into Community Edition, ships a bundled developer toolkit out of the box, and introduces a new **Minimal Distribution** option for teams that want to compose their own stack.

<Callout type="info" title="What's new in 3.0">

- Built on Magento Open Source 2.4.9
- PHP 8.5 support added (PHP 8.2 dropped)
- Symfony 7.4 LTS across the suite
- Adobe analytics modules removed
- RMA and Admin Activity Log now in Community Edition
- New developer toolkit bundled by default: magerun2, Ignition, Varnish Extended, Custom Admin Logo
- New **Minimal Distribution** for lean, hand-composed installs
- PHP 8.4 lazy-ghost object loading wired into core DI for faster cold-start performance

</Callout>

<Callout type="warning" title="Breaking changes — please read before upgrading">
- **PHP 8.2 is no longer supported.** Minimum is now PHP 8.3 (8.4 recommended).
- **Symfony 6.4 → 7.4 LTS.** Extensions that type-hint Symfony 6.x classes will need to be updated.
- **Adobe analytics modules are gone.** Any extension or script referencing `module-analytics`, `module-catalog-analytics`, `module-customer-analytics`, `module-marketplace`, `module-quote-analytics`, `module-review-analytics`, `module-sales-analytics`, or `module-wishlist-analytics` will fail to autoload.
- **JWT framework 3 → 4.** Review any custom JWT integrations.
- **Composer floor raised to ^2.2.** Composer 2.0/2.1 installs will be blocked.

See the [Compatibility & upgrade notes](#compatibility--upgrade-notes) section below for full details.

</Callout>

### What's new in Mage-OS 3.0

#### PHP 8.5 ready, with faster cold starts on 8.4

Mage-OS 3.0 supports PHP 8.5 alongside 8.3 and 8.4. As part of this release, we wired **PHP 8.4 lazy-ghost object loading** into the compiled DI factory, with `#[NonLazy]` markers on always-realized core classes. The result is meaningfully faster object graph construction on cold requests, with no behavioral change for extension authors.

#### Symfony 7.4 LTS across the board

Symfony Console, Intl, Mailer, Mime, Process, and String have all moved from `^6.4` to `^7.4`. This is a coordinated bump to Symfony's current LTS release, giving us a long support window and access to the latest framework improvements.

#### Adobe analytics modules removed

In line with the Mage-OS project's commitment to keeping merchant data on the merchant's server, **every Adobe `*-analytics` module and `module-marketplace` has been removed** from the dependency tree. There is no functional loss for stores: these modules existed to send usage telemetry to Adobe. Their removal also trims the install footprint and eliminates an entire surface of phone-home traffic.

#### RMA in Community Edition

`mage-os/module-rma` is now part of the Community Edition distribution. Customers can request product returns from their account, and merchants get the admin workflow to approve, ship, and refund them — a feature previously gated to Adobe Commerce.

{/* SCREENSHOT: customer-facing RMA request screen OR admin RMA grid */}

#### Admin Activity Log in Community Edition

`mage-os/module-admin-activity-log` brings admin action logging into CE, giving you a built-in audit trail for who changed what, when. This unlocks compliance and forensic use cases that previously required either a custom module or an Adobe Commerce license.

{/* SCREENSHOT: admin grid showing logged actions */}

#### New: Minimal Distribution

Alongside the full distribution, Mage-OS 3.0 introduces `mage-os/product-minimal-edition` — a lean install that ships only the ~98 core packages required for a functional store. Modules, themes, and language packs are available as individual Composer packages from the Mage-OS repository, so you only install what you actually use.

The Minimal Distribution is aimed at teams comfortable composing their own Mage-OS stack. It gives you a much smaller starting footprint, but expects you to know which packages your project actually needs.

Browse the included packages, and the full set of available add-ons, in the new [Package Browser](/product/minimal).

### New developer toolkit, bundled by default

Mage-OS 3.0 ships several well-loved community tools out of the box. These have been part of many Magento developers' workflows for years; bundling them lowers the friction of standing up a productive environment.

#### n98-magerun2

The de-facto Magento CLI swiss-army knife now ships in every new Mage-OS project. From `sys:info` and `cache:flush` to `db:console`, `dev:console`, and dozens of inspection commands, magerun2 is the tool most Magento developers reach for first.

Maintained by **[Elgentos](https://github.com/elgentos)** — Peter Jaap Blaakmeer and the Elgentos team.

### Compatibility & upgrade notes

Before upgrading, please review the following:

- **PHP 8.3 minimum.** Composer will refuse to resolve `mage-os/product-community-edition=3.0.0` on PHP 8.2 or earlier. PHP 8.4 is recommended for the lazy-ghost performance benefits; PHP 8.5 is also supported.
- **Symfony 6 → 7.** Any extension that type-hints classes from `symfony/console`, `symfony/intl`, `symfony/mailer`, `symfony/mime`, `symfony/process`, or `symfony/string` with the 6.x signature will need an update.
- **Adobe analytics removal.** If you have custom code that depends on any of the `*-analytics` modules or `module-marketplace`, remove the references before upgrading.
- **Transactional email rendering.** `pelago/emogrifier` jumped 7 → 8. Heavily-customized transactional templates should be tested for visual regressions.
- **JWT.** `web-token/jwt-framework` 3 → 4. Custom JWT integrations should be reviewed.
- **Composer 2.2+.** If you're on Composer 2.0 or 2.1, upgrade Composer first.

### Mirror updates

The latest Magento versions, including 2.4.9, are also available from our public Magento mirror at [mirror.mage-os.org](https://mirror.mage-os.org). ### Installation

#### New installations

```bash
composer create-project --repository-url=https://repo.mage-os.org/ mage-os/project-community-edition=3.0.0 <install-directory-name>
```

To try the new lean install instead, see the [Minimal Distribution](/product/minimal) page.

#### Upgrading from Mage-OS 2.3.x

<Callout type="warning" title="Confirm PHP 8.3+ before upgrading">
  Composer will refuse to resolve 3.0.0 on PHP 8.2 or earlier. Upgrade your runtime first.
</Callout>

```bash
composer require mage-os/product-community-edition=3.0.0 --no-update
composer update
bin/magento setup:upgrade
```

#### Upgrading from an older Mage-OS version

```bash
composer require mage-os/product-community-edition=^3.0 --no-update
composer update
bin/magento setup:upgrade
```
