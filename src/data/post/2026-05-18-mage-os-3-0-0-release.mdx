**Mage-OS Distribution 3.0.0** is built on **Magento Open Source 2.4.9**. Headline changes: a brand-new interactive installer, Return Merchandise Authorization (RMA) and Admin Activity Log in Community Edition, an "update available" indicator in the admin footer, a bundled developer toolkit, and an opt-in Minimal Distribution.

<Callout type="info" title="What's new in 3.0">

- **Interactive installer**: `bin/magento install` — guided wizard with service auto-detection and resume-on-failure
- Built on Magento Open Source 2.4.9
- PHP 8.5 added (PHP 8.2 dropped)
- Symfony 7.4 long-term support (LTS)
- Adobe analytics modules removed
- RMA and Admin Activity Log now in Community Edition
- New developer toolkit bundled by default: magerun2, Ignition, Varnish Extended, Custom Admin Logo
- New **Minimal Distribution** for lean, hand-composed installs
- "Update available" indicator in the admin footer
- PHP 8.4 lazy-ghost object loading in core dependency injection (DI) for faster cold starts

</Callout>

<Callout type="warning" title="Breaking changes — please read before upgrading">

- **PHP 8.2 is no longer supported.** Minimum is now PHP 8.3 (8.4 recommended).
- **Symfony 6.4 → 7.4 LTS.** Extensions type-hinting Symfony 6.x classes need updates.
- **Adobe analytics modules removed.** Extensions referencing them will fail to autoload.
- **JSON Web Token (JWT) framework 3 → 4.** Review custom JWT integrations.
- **Composer floor raised to `^2.2`.**

See the [Compatibility & upgrade notes](#compatibility--upgrade-notes) for the full list.

</Callout>

## What's new in Mage-OS 3.0

### Interactive installer: `bin/magento install`

The biggest quality-of-life win in 3.0:

```bash
bin/magento install
```

A guided wizard walks you through database, admin account, store config, services, sample data, and theme selection. Along the way it:

- **Auto-detects services** — MySQL/MariaDB, Redis, OpenSearch/Elasticsearch, and RabbitMQ on common ports.
- **Resumes on failure** — config is saved; the next run picks up where you left off (passwords are re-prompted).
- **Protects production** — explicit confirmations before destructive operations; warns if it suspects production.
- **Handles post-install setup** — applies the chosen theme, sets indexers to schedule mode, manages two-factor authentication (2FA), and flushes caches.

The original `setup:install` is unchanged, so automation isn't affected. Contributed by [@DavidLambauer](https://github.com/DavidLambauer) with 410 unit tests ([#191](https://github.com/mage-os/mageos-magento2/pull/191)).

### PHP 8.5 ready, faster cold starts on 8.4

Mage-OS 3.0 supports PHP 8.5 alongside 8.3 and 8.4. **PHP 8.4 lazy-ghost object loading** is wired into the compiled DI factory (with `#[NonLazy]` markers on always-realized core classes) for noticeably faster cold-request bootstrapping — transparent to extension authors.

### Symfony 7.4 LTS

Symfony Console, Intl, Mailer, Mime, Process, and String all move from `^6.4` to `^7.4` — the current LTS line.

### Adobe analytics modules removed

Keeping with the Mage-OS commitment to leaving merchant data on the merchant's server, **every Adobe `*-analytics` module and `module-marketplace` is gone**. No functional loss — these modules existed to send usage telemetry to Adobe. The install footprint shrinks and an entire outbound-telemetry surface is eliminated.

### RMA in Community Edition

`mage-os/module-rma` is now part of Community Edition. Customers request returns from their account; merchants approve, ship, and refund from the admin — previously Adobe Commerce only.

{/* SCREENSHOT: customer-facing RMA request screen OR admin RMA grid */}

### Admin Activity Log in Community Edition

`mage-os/module-admin-activity-log` brings admin action logging into Community Edition — a built-in audit trail of who changed what, when. Previously required a custom module or Adobe Commerce.

{/* SCREENSHOT: admin grid showing logged actions */}

### "Update available" indicator in the admin footer

The admin footer now shows an **"Update available: X.Y.Z"** link when a newer stable release of your distribution package is available in your configured Composer repositories. Major/minor bumps render bold red; patch releases render normal weight.

- **Zero render cost** — the HTTP lookup runs in an hourly cron; the footer only reads from cache.
- **Fail-safe** — every failure path returns silently; a broken check can't break an admin page.
- **Respects your repos** — discovered from your `composer.json`, so private mirrors check against themselves.
- **Configurable** — toggle via `system/version_check/enabled`; cache TTL and link target are tunable.

{/* SCREENSHOT: Mage-OS admin footer showing the 'Update available' notice */}

Contributed by [@rhoerr](https://github.com/rhoerr) ([#207](https://github.com/mage-os/mageos-magento2/pull/207)).

### Minimal Distribution

3.0 introduces `mage-os/product-minimal-edition` — a lean install with only the ~98 core packages needed for a functional store. Modules, themes, and language packs are available as individual Composer packages, so you only install what you use. Best for teams comfortable composing their own stack.

Browse the included packages and the full add-on set in the new [Package Browser](/product/minimal).

## Developer toolkit, bundled by default

Mage-OS 3.0 bundles four long-standing community tools out of the box, lowering the friction of standing up a productive environment.

### n98-magerun2

The de-facto Magento command-line interface (CLI), now shipped by default. `sys:info`, `cache:flush`, `db:console`, `dev:console`, and dozens of inspection commands — usually the first tool reached for.

{/* SCREENSHOT: terminal showing magerun2 sys:info or dev:console output */}

Maintained by **[netz98 GmbH](https://github.com/netz98)** — Christian Münch ([@cmuench](https://github.com/cmuench)), Tom Klingenberg ([@kissifrot](https://github.com/kissifrot)) and the n98-magerun2 contributors.

### Ignition for Magento

A contextual error page for developer mode — stack traces, request context, environment details, and editor-jump links. Disabled in production, so it can't leak internals.

{/* SCREENSHOT: Ignition styled error page in developer mode */}

Maintained by **[Swissup Labs](https://github.com/swissup)**.

### Varnish Extended

Richer cache controls and operational tooling for teams running Varnish in production.

Maintained by **[Elgentos](https://github.com/elgentos)** — Peter Jaap Blaakmeer and the Elgentos team.

### Custom Admin Logo

Replace the admin panel and login-screen logo without touching a theme — a small but frequently-requested branding touch.

Maintained by **[element119](https://github.com/element119)** — Kiel Pykett ([@kpykett](https://github.com/kpykett)).

## Compatibility & upgrade notes

- **PHP 8.3 minimum.** Composer will refuse to resolve 3.0.0 on PHP 8.2 or earlier. PHP 8.4 is recommended; 8.5 is supported.
- **Symfony 6 → 7.** Extensions type-hinting `symfony/console`, `symfony/intl`, `symfony/mailer`, `symfony/mime`, `symfony/process`, or `symfony/string` 6.x signatures need updates.
- **Adobe analytics removal.** Remove references to `module-analytics`, `module-catalog-analytics`, `module-customer-analytics`, `module-marketplace`, `module-quote-analytics`, `module-review-analytics`, `module-sales-analytics`, and `module-wishlist-analytics` before upgrading.
- **Transactional email.** `pelago/emogrifier` 7 → 8 — test heavily-customized templates.
- **JWT.** `web-token/jwt-framework` 3 → 4 — review custom integrations.
- **Composer 2.2+.** Upgrade Composer if you're on 2.0/2.1.
- **`ext-ftp` dropped.** No longer required; hosting providers and container images can stop installing it.
- **`Magento_Backup` module removed.** The legacy `bin/magento setup:backup` command is gone — use filesystem and database backup tooling appropriate for your environment.
- **Shipping rate trimming reverted.** A 2.x change that trimmed shipping address fields before rate collection was rolled back in [#251](https://github.com/mage-os/mageos-magento2/pull/251). Behavior is pre-trim default; a fixed version may land in 3.0.1.

## Installation

### New installations

```bash
composer create-project --repository-url=https://repo.mage-os.org/ mage-os/project-community-edition=3.0.0 <install-directory-name>
cd <install-directory-name>
bin/magento install
```

The wizard detects local services, walks you through configuration, and handles post-install setup. `bin/magento setup:install` still works if you prefer the classic flow.

For the lean install, see the [Minimal Distribution](/product/minimal) page.

### Upgrading from Mage-OS 2.3.x

<Callout type="warning" title="Confirm PHP 8.3+ before upgrading">
  Composer will refuse to resolve 3.0.0 on PHP 8.2 or earlier. Upgrade your runtime first.
</Callout>

```bash
composer require mage-os/product-community-edition=3.0.0 --no-update
composer update
bin/magento setup:upgrade
```

### Upgrading from an older Mage-OS version

```bash
composer require mage-os/product-community-edition=^3.0 --no-update
composer update
bin/magento setup:upgrade
```
